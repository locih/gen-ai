# Постмортем инцидента SYNC-17 (январь 2025)

Постмортем инцидента SYNC-17 (январь 2025)

Инцидент SYNC-17 произошёл в период с 14 по 16 января 2025 года и затронул работу мобильного приложения «ФинУчёт». В результате сбоя 12% активных пользователей потеряли транзакции, что привело к частичной утрате данных о расходах за указанный период. Проблема была выявлена по жалобам пользователей, которые сообщили о пропаже записей после синхронизации с сервером. Внутренний мониторинг зафиксировал аномалии в работе Cloud Sync Worker, что позволило оперативно начать расследование.

Основной причиной инцидента стал баг в Cloud Sync Worker — дублирование offset при обработке очереди синхронизации. Это приводило к тому, что некоторые транзакции не записывались в основную базу данных, а их offset-маркеры сбрасывались в ноль. В результате при повторной синхронизации система считала часть данных уже обработанными и не сохраняла их. Дополнительно была зафиксирована проблема с таймаутом API Gateway 30 секунд, который не позволял завершить длительные запросы от клиентов с большим объёмом изменений. Это усугубило ситуацию, так как пользователи не могли повторно отправить данные после первого сбоя.

Восстановление заняло 18 часов, что соответствует показателю MTTR 18 часов. Команда мобильного приложения «ФинУчёт» сначала локализовала баг в Cloud Sync Worker, затем выполнила откат изменений в конфигурации offset. После этого была проведена повторная синхронизация данных для всех затронутых пользователей, что позволило восстановить потерянные транзакции. Для предотвращения подобных инцидентов в будущем добавлены дополнительные проверки корректности offset и увеличен лимит таймаута API Gateway до 60 секунд для запросов синхронизации.

Анализ инцидента показал, что баг в Cloud Sync Worker — дублирование offset — возник из-за ошибки в логике обработки конкурентных запросов. В условиях высокой нагрузки на сервис синхронизации offset сбрасывался для нескольких транзакций одновременно, что вызывало потерю данных. Таймаут API Gateway 30 секунд не был рассчитан на пиковые нагрузки, что привело к блокировке запросов от пользователей с большим количеством операций. В результате 12% активных пользователей потеряли транзакции, что стало критическим сбоем для сервиса учёта расходов.

Для устранения последствий инцидента SYNC-17 были предприняты следующие шаги: проведён аудит кода Cloud Sync Worker, добавлены unit-тесты для сценариев с дублированием offset, а также увеличен таймаут API Gateway до 60 секунд. Команда мобильного приложения «ФинУчёт» также разработала план по внедрению механизма автоматического восстановления данных при обнаружении аномалий в синхронизации. Эти меры позволят снизить риск повторения инцидента и сократить время восстановления в будущем.

Выводы по инциденту SYNC-17 указывают на необходимость усиления мониторинга Cloud Sync Worker и API Gateway. Рекомендуется внедрить предупреждения о превышении лимитов таймаута и аномалиях offset, а также регулярно проводить нагрузочное тестирование сценариев синхронизации. Дополнительно следует обновить документацию по обработке конкурентных запросов для предотвращения дублирования offset. Внедрение этих улучшений запланировано на февраль 2025 года.

Коммуникация с пользователями велась через in-app баннер и email: затронутым аккаунтам отправили push о завершении восстановления и ссылку на FAQ. Команда поддержки получила скрипт ответов с упоминанием MTTR 18 часов и причин инцидента. NPS среди пострадавших упал на 12 пунктов, восстановление лояльности заложено в Q1 roadmap.
