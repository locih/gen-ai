# Выводы - Семинар 4

## 1. Корпус

Внутренняя документация команды мобильного приложения «ФинУчёт» (постмортемы, ADR, исследования, спеки поддержки и монетизации). **10 документов**, суммарно **~69 300 символов**, каждый файл - 500–520 слов.

## 3. Результаты

Гибридный retrieval: dense (ChromaDB) + BM25 + RRF. Метрика **hit-rate@5**.

| Стратегия | Описание | hit-rate@5 |
|-----------|----------|------------|
| **A** - fixed-size | `text[i : i+2000]`, без перекрытия | **0.91** (10.0/11) |
| **B** - recursive | `chunk_size=400`, `overlap=80` | **0.95** (10.5/11) |

**Δ = +0.05** в пользу стратегии B.

Запуск: `python pipeline.py ingest --strategy {a|b}`, затем `python eval.py`.

## 4. Анализ ошибок

### Q4 - multi-hop: A miss, B hit

**Вопрос:** «Как реклама связана с оттоком в первую неделю после установки?»

| | Топ-5 источников |
|---|------------------|
| **A** | research_ads_churn ×2, support_q1, ab_test_premium, postmortem_sync_jan |
| **B** | research_ads_churn ×4, **onboarding_funnel** |

Стратегия A нашла документ про рекламу, но **не подтянула** `onboarding_funnel` (там «первая неделя - критический период»). Крупный чанк `research_ads_churn` (~3.5 КБ) доминирует в эмбеддинге, а сигнал из воронки онбординга размыт во втором файле. Recursive нарезал `onboarding_funnel` на 16 чанков - один с формулировкой про первую неделю попал в топ-5 рядом с чанками про 41% uninstall.

### Q9 - оба стратегии: hit=0.5

**Вопрос:** «Как 152-ФЗ связан с хранением биометрии и локальной базой на устройстве?»

Оба варианта находят `security_biometrics`, но **не** `adr_sqlite_cache`. Запрос семантически ближе к регуляторике и Face ID; ADR про SQLite WAL попадает в топ только при явном упоминании «база» / «кэш». В `security_biometrics` добавлена отсылка к ADR-007, но этого недостаточно для dense+BM25 при формулировке про 152-ФЗ.

### Q2 - оба hit, но B точнее

**Вопрос:** синоним к «медленный запуск 4.2 с на Redmi».

Стратегия A: в топ-5 только один чанк `perf_audit_android`, остальное - research_ads, adr_sqlite. Стратегия B: четыре чанка из `perf_audit_android` - релевантный абзац на первой позиции.

## 5. Вывод

Стратегия **B (recursive 400/80)** выиграла: hit-rate@5 = **0.95** против **0.91** у A. Мелкие чанки концентрируют тему абзаца - это критично для multi-hop (#4), где нужны два разных документа. Fixed-size на коротких внутренних текстах (~7 КБ) ещё работает, но чаще смешивает темы в одном векторе. Для production: recursive + гибрид BM25 (как в `pipeline.py`) - особенно для кодов вроде EXP-204 и 152-ФЗ.
